2.8.0

4 nov 2026Nov 4, 2026
Mais recenteLatest

Menos chamadas onde uma regra basta, menos dicas, e duas medições para saber se o ClauJev ajuda.

Fewer calls where a rule is enough, fewer hints, and two measurements to tell whether ClauJev helps.

  • MudouChanged

    git push, gh pr merge, branch -D, reset --hard, npm publish, DROP TABLE e parecidos pedem confirmação por uma regra local, sem chamar o Jev: o mesmo resultado, sem custo e sem espera. As dicas de tamanho na triagem ficam desligadas por padrão (sizeHints).

    git push, gh pr merge, branch -D, reset --hard, npm publish, DROP TABLE and the like ask for confirmation by a local rule, without calling Jev: the same outcome, at no cost or wait. Size hints in triage are off by default (sizeHints).

  • NovoNew

    O report mostra se a checagem final ajudou (depois de um bloqueio, o Claude mudou algo ou só explicou) e quantas sugestões de esforço você aceitou, manteve ou fechou.

    report shows whether the final check helped (after a block, Claude changed something or only explained) and how many effort suggestions you accepted, kept or dismissed.

2.7.0

4 nov 2026Nov 4, 2026

Edições feitas pelo shell voltam a ser checadas, e o esforço passa a pesar a investigação, não só o código.

Edits made through the shell are checked again, and effort now weighs investigation, not just code.

  • CorrigidoFixed

    No modo automático, o Claude Code edita arquivos com sed, python ou heredoc no Bash, e essas edições não passavam pela revisão de regras. Em dois dias foram 117 chamadas de Bash e 1 de Edit. Agora cada sessão pede edições por Edit/Write e, se um comando do shell escrever arquivos mesmo assim, a checagem final lê do git o que mudou no turno.

    In auto mode Claude Code edits files with sed, python or heredocs in Bash, and those edits skipped the rule review. In two days there were 117 Bash calls and 1 Edit. Now each session asks for edits through Edit/Write, and when a shell command still writes files, the final check reads what changed in the turn from git.

  • CorrigidoFixed

    A dica "a mudança parece pequena" não aparece mais em respostas de conversa, e o aviso de limite de uso resetado não é triado como pedido novo.

    The "the change looks small" hint no longer shows up on chat replies, and the usage-limit resume message is no longer triaged as a new request.

  • MudouChanged

    O esforço considera também quanta investigação o pedido exige. Revisar logs ou testes instáveis não sai mais low só porque não mexe em código. Em 40 pedidos reais, a sugestão acertou 35, contra 25 antes.

    Effort also weighs how much investigation the request needs. Reviewing logs or flaky tests no longer gets low just because no code changes. On 40 real requests, the suggestion was right in 35, against 25 before.

2.6.1

2 nov 2026Nov 2, 2026

Carregar um .env para rodar um script local não parece mais meio destrutivo.

Loading an .env to run a local script no longer looks half destructive.

  • CorrigidoFixed

    A guarda de comandos julga pelo que o comando mostra: carregar variáveis e rodar um script cujo nome não diz que apaga, faz deploy, migra, popula ou escreve em sistema remoto não é destrutivo por si só. Em 15 comandos reaplicados, set -a; . .env; node scripts/sync.mjs caiu de 0,68 para 0,46 e os outros seguros para 0,05–0,22. Todos os destrutivos ficaram iguais ou mais altos.

    The command guard judges by what the command shows: loading variables and running a script whose name doesn't say it deletes, deploys, migrates, seeds or writes remotely is not destructive by itself. On 15 replayed commands, set -a; . .env; node scripts/sync.mjs went from 0.68 to 0.46 and other safe ones to 0.05–0.22. Every destructive one scored the same or higher.

2.6.0

2 nov 2026Nov 2, 2026

Pronto para usar desde a instalação, e o esforço só muda com o seu sim.

Ready to use from install, and the effort only changes with your yes.

  • MudouChanged

    Padrão opinativo: o ClauJev já age ao ser instalado. Triagem, guarda de comandos, revisão por regras, conferência final e checagem de relatórios de subagentes vêm em enforce. Só o roteamento de subagentes continua em observe, porque trocar o modelo de um subagente sem perguntar pode piorar o resultado. Quem já escolheu um modo em /claujev:configure mantém a escolha.

    Opinionated defaults: ClauJev acts from install. Triage, command guard, rule review, final check and subagent report check default to enforce. Only subagent routing stays in observe, since moving a subagent to a smaller model unasked can cost quality. Anyone who picked a mode in /claujev:configure keeps it.

  • MudouChanged

    O mod pergunta antes de mudar o esforço (claujev-mod 2.2.0). Quando a sugestão do Jev é diferente do esforço em uso, a caixa de pergunta do Claude Code abre: "O Jev acha este pedido simples. Usar esforço low em vez de high?". O pedido roda com o que você escolher, e Esc mantém o atual. É o novo padrão, ask; observe, on e off continuam em /claujev:configure.

    The mod asks before changing the effort (claujev-mod 2.2.0). When Jev's suggestion differs from the effort in use, Claude Code's question dialog opens: "Jev thinks this request is simple. Use low effort instead of high?". The request runs with what you pick, and Esc keeps the current one. It's the new default, ask; observe, on and off stay in /claujev:configure.

  • CorrigidoFixed

    A documentação não dá mais a entender que o esforço muda sozinho: "esforço automático" virou "sugestão de esforço".

    The docs no longer imply the effort changes by itself: "automatic effort" is now "effort suggestion".

2.5.0

2 nov 2026Nov 2, 2026

Mais precisão, ajustada com 7.643 eventos reais. A conferência final passa a ler a resposta do Claude, e a guarda de credenciais separa usar uma chave de expor uma chave.

More accurate, tuned on 7,643 real events. The final check now reads Claude's reply, and the credential guard tells using a key apart from exposing it.

244alertas na conferência final, em 40 turnosfinal-check alerts, out of 40 turns
1006alertas de credenciaiscredential alerts
12%menos chamadas ao Jev, sem perder alertafewer Jev calls, no alert lost
  • MudouChanged

    A conferência final lê a resposta do Claude. O Jev vê o que o Claude diz que fez (até 3.000 caracteres, sem segredos), o pedido anterior e os comandos do turno, com mais detalhe nos que têm efeito. Uma pendência explicada na resposta conta como relatada, não como esquecida.

    The final check reads Claude's reply. Jev sees what Claude says it did (up to 3,000 characters, secrets removed), the previous request and the turn's commands, with more detail on the ones that have effects. Work left pending and explained in the reply counts as reported, not forgotten.

  • MudouChanged

    Credenciais: expor, não usar. A pergunta agora é se o comando mostra, copia ou envia uma credencial. Carregar um .env para rodar um script local não conta. cat .env, echo $KEY e gh auth token continuam entre 0,81 e 0,99.

    Credentials: exposure, not use. The question is now whether a command shows, copies or sends a credential. Loading an .env so a local script can run doesn't count. cat .env, echo $KEY and gh auth token still score 0.81–0.99.

  • MudouChanged

    Comandos destrutivos. git add e commit locais e arquivos temporários contam como fáceis de desfazer. Push, merge, deploy e migration, não.

    Destructive commands. Local git add and commit and temporary files count as easy to undo. Push, merge, deploys and migrations don't.

  • MudouChanged

    Limiares. incomplete 0,30 / 0,50 (era 0,25 / 0,40) e credentials 0,45 / 0,65 (era 0,50 / 0,70).

    Thresholds. incomplete 0.30 / 0.50 (was 0.25 / 0.40) and credentials 0.45 / 0.65 (was 0.50 / 0.70).

  • CorrigidoFixed

    Atalho de leitura em comandos reais. 65% dos comandos começam com cd … &&, e todos iam ao Jev. Agora cada parte do encadeamento é conferida, então cd repo && git status | head passa direto. Redirecionamento, substituição, sed -i, & e arquivos sensíveis continuam indo ao Jev.

    Read-only shortcut works on real commands. 65% of commands start with cd … &&, and all of them went to Jev. Each part of a chain is now checked, so cd repo && git status | head goes straight through. Redirection, substitution, sed -i, & and sensitive files still go to Jev.

  • CorrigidoFixed

    Comandos que só parecem leitura. git branch -D, find -execdir, rg --pre, PATH=… antes de um comando, echo $API_KEY, jq -n env e arquivos como .netrc e o hosts.yml do gh passam a ir ao Jev.

    Commands that only look like reads. git branch -D, find -execdir, rg --pre, PATH=… before a command, echo $API_KEY, jq -n env and files such as .netrc and gh's hosts.yml now go to Jev.

  • CorrigidoFixed

    Mensagens do sistema fora da triagem. <task-notification> e outras mensagens que o Claude Code injeta não são mais triadas como pedidos, nem substituem o pedido que a conferência final usa.

    System messages skip triage. <task-notification> and other messages Claude Code injects are no longer triaged as requests, nor do they replace the request the final check compares against.

  • CorrigidoFixed

    Respostas de conversa menos "ambíguas". A triagem recebe o pedido anterior como contexto.

    Conversation replies are less "ambiguous". Triage now gets the previous request as context.

2.4.2

20 out 2026Oct 20, 2026

Rede de segurança na guarda de comandos.

A safety net for the command guard.

  • CorrigidoFixed

    Quando o Jev não responde a tempo, comandos claramente destrutivos (push --force, reset --hard, rm -rf, DROP TABLE, npm publish…) ainda pedem confirmação no modo enforce, por uma checagem local. Os outros comandos seguem, e a sessão nunca trava por erro.

    When Jev can't answer in time, plainly destructive commands (push --force, reset --hard, rm -rf, DROP TABLE, npm publish…) still ask for confirmation in enforce mode, from a local check. Other commands pass, so the session never blocks on an error.

2.4.1

20 out 2026Oct 20, 2026

Chave escrita no código é pega na sua máquina.

Keys written in code are caught on your machine.

  • CorrigidoFixed

    O Jev só vê o código depois que os segredos são removidos, então uma chave escrita no código passava como "incerta". Agora a revisão por regras detecta segredos literais localmente (api_key, token ou password entre aspas, sk-…, ghp_…, chaves privadas), e o segredo nunca sai da máquina. Código que só lida com segredos, como process.env.API_KEY, não é marcado.

    Jev only sees code after secrets are removed, so a key written in code scored as "uncertain". Rule review now detects literal secrets locally (quoted api_key, token or password values, sk-…, ghp_…, private keys), and the secret never leaves the machine. Code that only handles secrets, like process.env.API_KEY, isn't flagged.
